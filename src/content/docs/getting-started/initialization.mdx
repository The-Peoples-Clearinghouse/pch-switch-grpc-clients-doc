El cliente gRPC requiere tres parámetros principales para establecer la conexión: el identificador del participante (`fspId`), la dirección del servidor, y los archivos de certificados.
Una vez inicializado, el cliente establece el stream autenticado mediante `StartStream` antes de que puedas enviar cualquier operación.

## Inicializar y conectar

<Tabs syncKey="lenguaje">
  <TabItem label="TypeScript">
    ```typescript
    import {
      GrpcSyncApiClient,
      IGrpcClientSecurityOptions,
      CryptoAndCertHelper,
    } from "@pch-private/interop-apis-bc-grpc-sync-client-lib";
    import { readFileSync } from "fs";

    const clientSecurityOptions: IGrpcClientSecurityOptions = {
      mode: "SERVER_TLS",
      caCertFilePath: "./certs/hub-intermediate.pem",
      clientPrivateKeyFilePath: "./certs/participant_authentication.key",
      clientCertFilePath: "./certs/participant_authentication.pem",
    };

    // Lee el certificado del participante como texto PEM
    const clientCertPem = readFileSync(
      clientSecurityOptions.clientCertFilePath!,
      "utf-8"
    );

    // CryptoAndCertHelper maneja la firma y validación criptográfica del flujo StartStream
    const cryptoAndCertHelper = new CryptoAndCertHelper(
      clientSecurityOptions.clientPrivateKeyFilePath!,
      clientSecurityOptions.caCertFilePath!
    );

    // Segunda instancia de CryptoAndCertHelper, con las llaves de firma de transacciones.
    // No participa en StartStream: guárdala para firmar payerSignature/payeeSignature
    // cuando ejecutes una transferencia (ver la guía de Ejecutar transferencia).
    const transactionSigningHelper = new CryptoAndCertHelper(
      "./certs/participant_transaction_signing.key",
      "./certs/hub-intermediate-transaction-signing.pem"
    );

    const grpcClient = new GrpcSyncApiClient(
      "switch.camara.mx:443",    // dirección del servidor gRPC
      "MIBANCO",                 // fspId: debe coincidir con el del certificado
      clientCertPem,
      cryptoAndCertHelper,
      clientSecurityOptions
    );

    await grpcClient.init();
    console.log("Cliente conectado y autenticado");
    ```

    ```java
    import com.pch.grpc.application.GrpcSyncApiClient;
    import com.pch.grpc.application.GrpcTlsSecurityMode;
    import com.pch.grpc.application.IGrpcClientSecurityOptions;
    import com.pch.grpc.infrastructure.security.CryptoAndCertHelper;
    import java.nio.charset.StandardCharsets;
    import java.nio.file.Files;
    import java.nio.file.Paths;

    String caCertPem = new String(
      Files.readAllBytes(Paths.get("./certs/hub-intermediate.pem")),
      StandardCharsets.UTF_8
    );
    String clientPrivateKey = new String(
      Files.readAllBytes(Paths.get("./certs/participant_authentication.key")),
      StandardCharsets.UTF_8
    );
    String clientCertPem = new String(
      Files.readAllBytes(Paths.get("./certs/participant_authentication.pem")),
      StandardCharsets.UTF_8
    );

    // Llaves de firma de transacciones — jerarquía de CA distinta a la de autenticación.
    String transactionSigningCaCertPem = new String(
      Files.readAllBytes(Paths.get("./certs/hub-intermediate-transaction-signing.pem")),
      StandardCharsets.UTF_8
    );
    String transactionSigningKey = new String(
      Files.readAllBytes(Paths.get("./certs/participant_transaction_signing.key")),
      StandardCharsets.UTF_8
    );

    IGrpcClientSecurityOptions clientSecurityOptions = () -> GrpcTlsSecurityMode.SERVER_TLS;

    // CryptoAndCertHelper maneja la firma y validación criptográfica del flujo StartStream
    CryptoAndCertHelper cryptoHelper = new CryptoAndCertHelper(clientPrivateKey, caCertPem);

    // Segunda instancia, con las llaves de firma de transacciones. El constructor la exige
    // — no hay fallback, ni siquiera para desarrollo local.
    CryptoAndCertHelper transferCryptoHelper =
      new CryptoAndCertHelper(transactionSigningKey, transactionSigningCaCertPem);

    GrpcSyncApiClient grpcClient = new GrpcSyncApiClient(
        "switch.camara.mx:443",   // dirección del servidor gRPC
        "MIBANCO",                // fspId: debe coincidir con el del certificado
        clientCertPem,
        clientPrivateKey,
        caCertPem,
        cryptoHelper,
        transferCryptoHelper,     // firma/verifica payerSignature, payeeSignature y las firmas del switch
        clientSecurityOptions
    );

    if (!grpcClient.init()) {
        throw new RuntimeException("No se pudo abrir el stream o autenticar");
    }
    System.out.println("Cliente conectado y autenticado");
    ```

## Parámetros de configuración

| Parámetro | Descripción |
|---|---|
| `fspId` | Identificador del participante. Debe coincidir exactamente con el del certificado. |
| `host` | Dirección y puerto del Switch (proporcionados por la Cámara). |
| `privateKeyPath` | Ruta al archivo `participant_authentication.key`. |
| `certificatePath` | Ruta al archivo `participant_authentication.pem`. |
| `caCertificatePath` | Ruta al archivo `hub-intermediate.pem`. |

Además, para poder firmar transferencias más adelante, ten disponibles desde el arranque:

| Parámetro | Descripción |
|---|---|
| `transactionSigningPrivateKeyPath` | Ruta al archivo `participant_transaction_signing.key`. |
| `transactionSigningCaCertificatePath` | Ruta al archivo `hub-intermediate-transaction-signing.pem`. |

## CryptoAndCertHelper

`CryptoAndCertHelper` es la implementación de referencia proporcionada por la Cámara para el manejo criptográfico de firmas. Aplica a **TypeScript, Java y C#** (PHP no usa esta interfaz — ver la nota en su pestaña de la sección anterior). Vas a instanciarla dos veces, una por cada jerarquía de certificados:

- La instancia construida con las llaves de **autenticación** se pasa al constructor de `GrpcSyncApiClient` en los tres lenguajes, y el cliente la usa internamente para firmar el reto y validar la firma de respuesta del hub durante `StartStream`.
- La instancia construida con las llaves de **firma de transacciones** se comporta distinto según el lenguaje:
  - En **Java y C#**, el constructor de `GrpcSyncApiClient` la exige como segundo parámetro (`transferCryptoAndCertHelper`) — es obligatoria, no hay fallback. El cliente la usa internamente en `signTransferRequest(request)` y `verifyTransferResponseSignature(response)`, así que no necesitás armar el string canónico a mano.
  - En **TypeScript**, el cliente no la recibe ni la usa — la mantiene tu aplicación y la usás directamente con `signString` para firmar `payerSignature`/`payeeSignature`, armando el contenido canónico vos mismo (ver la guía de Ejecutar transferencia).

Ambas instancias exponen la misma interfaz; solo cambian las llaves con las que se construyen.

En TypeScript, el cliente acepta cualquier objeto que implemente la interfaz `ICryptoAndCertHelper`:

```typescript
export interface ICryptoAndCertHelper {
  signString(stringToSign: string): Promise<string>;
  validateSignature(
    signedString: string,
    signature: string,
    pubKeyFingerprint: string
  ): Promise<boolean>;
}
```

Java y C# exponen la misma interfaz más un tercer método, usado por `verifyTransferResponseSignature` y las demás verificaciones del flujo de transferencia:

- **`verifySwitchSignature(data, signature)`** — Verifica una firma del switch usando la llave pública del certificado CA cargado en esa instancia (sin comparar fingerprint, a diferencia de `validateSignature`, que sí lo hace y solo aplica al handshake inicial).

La implementación de la Cámara cubre los métodos requeridos:

- **`signString`** — Firma el reto (o, en la instancia de firma de transacciones, el contenido canónico) con la llave privada correspondiente usando RSA + SHA-256. Devuelve la firma en Base64.
- **`validateSignature`** — Verifica la firma del hub durante `StartStream`, usando la llave pública extraída del certificado intermedio de la CA cargado en esa instancia. Antes de verificar, compara el fingerprint de la llave pública recibida contra el del certificado cargado; si no coinciden, rechaza la validación sin intentar verificar. La firma llega en Base64 y se decodifica como tal antes de pasarla al verificador.

<Aside type="tip">
  Puedes proporcionar tu propia implementación de `ICryptoAndCertHelper` si necesitas integrar con un HSM, un servicio de firma externo, o un algoritmo diferente. Solo asegúrate de que `signString` produzca una firma compatible con el algoritmo configurado en el Switch para tu participante.
</Aside>

## Manejar desconexiones

El cliente mantiene el stream activo, pero pueden ocurrir desconexiones por inactividad o errores de red. Registra un handler para reconectarte automáticamente.
