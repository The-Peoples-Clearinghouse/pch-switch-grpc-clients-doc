`ProcessOfflineTransferCertificates` presenta al Switch los certificados de los pagos offline que ya ocurrieron entre dispositivos, para que se validen y se acrediten. Se envían todos los certificados pendientes de un mismo dispositivo en una sola llamada, y la respuesta trae un resultado por cada uno.

<Aside type="note">
  Tanto el dispositivo del pagador como el del beneficiario conservan una copia del certificado y cualquiera de los dos puede presentarlo. Un certificado ya acreditado no genera un segundo cargo.
</Aside>

## Enviar la solicitud

    const attestationInfo = new AttestationInfo();
    attestationInfo.setChallengeid(challengeId);
    attestationInfo.setPackagename('mx.mibanco.app');
    attestationInfo.setToken(attestationToken);

    const request = new ProcessOfflineTransferCertificatesRequest();
    request.setSourcefspid('MIBANCO');
    request.setRequesterpublickeyhash(devicePublicKeyHash);
    request.setAttestationinfo(attestationInfo);
    // Certificados construidos y firmados por la app durante los pagos offline
    request.setCertificatesList(certificados);

    // Envía la solicitud al Switch
    const grpcResponse = await grpcClient.processOfflineTransferCertificates(request);

    // Maneja el resultado de cada certificado por separado
    for (const result of grpcResponse.getResultsList()) {
      const transactionId = result.getTransactionid();

      if (result.getSuccess()) {
        marcarPagoAcreditado(transactionId);
        continue;
      }

      const error = result.getError();
      console.error(`Pago ${transactionId} rechazado:`, error?.getCode(), error?.getMessage());
    }

## Parámetros de la solicitud

| Campo | Tipo | Requerido | Descripción |
|---|---|---|---|
| `sourceFspId` | `string` | Sí | FSP que origina la solicitud (el Participante). |
| `requesterPublicKeyHash` | `string` | Sí | Hash de la llave pública del dispositivo que presenta los certificados. |
| `attestationInfo` | `AttestationInfo` | Sí | Resultado de la atestación del dispositivo: `challengeId`, `packageName` y `token`. |
| `certificates` | `OfflinePaymentCertificate[]` | Sí | Certificados de los pagos offline a acreditar. Ver tabla siguiente. |

### OfflinePaymentCertificate

| Campo | Tipo | Descripción |
|---|---|---|
| `paymentProposal` | `PaymentProposal` | Propuesta de pago: `transactionId`, `amount`, `currency`, `note`, datos del pagador y del beneficiario, `createdAt`, `expiresAt` y los `tokens` utilizados. |
| `payeeAcceptance` | `PayeeAcceptance` | Aceptación del beneficiario: `acceptedAt`, `paymentProposalSignedByPayee` y `publicKeyHash`. |
| `payerAuthorization` | `PayerAuthorization` | Autorización del pagador: `authorizedAt`, `payeeAcceptanceSignedByPayer` y `publicKeyHash`. |
| `rejectionReasonCode` | `string` | Opcional. |

## Respuesta

| Campo | Tipo | Descripción |
|---|---|---|
| `results` | `ProcessOfflineTransferCertificateResult[]` | Un resultado por cada certificado enviado. |

### ProcessOfflineTransferCertificateResult

| Campo | Tipo | Descripción |
|---|---|---|
| `transactionId` | `string` | Identificador del pago offline al que corresponde el resultado. |
| `success` | `boolean` | `true` si el pago se acreditó. |
| `error` | `ErrorResponse` | Motivo del rechazo, cuando `success` es `false`. |

<Aside type="caution">
  Cada certificado se resuelve por separado: que uno sea rechazado no afecta a los demás. Recorre siempre la lista completa de resultados y no des por acreditado el lote entero.
</Aside>
