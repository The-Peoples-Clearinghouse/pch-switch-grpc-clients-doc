Cuando el dispositivo del pagador o del beneficiario recupera la conexión, la app presenta el pago offline. Después de validarlo, el Switch envía al Participante del pagador una solicitud `SettleOfflineTransfer`. El Participante debe acreditar el pago contra la reserva offline del Cliente pagador y responder con el resultado.

Para recibir estas solicitudes, debes registrar un **handler** en el cliente gRPC. El cliente invocará esta función una vez por cada pago offline a acreditar.

<Aside type="caution">
  El mismo pago puede llegar más de una vez, ya que tanto el pagador como el beneficiario pueden presentarlo. **Solo la primera solicitud válida debe generar el cargo.** Si recibes un `transactionId` que ya procesaste, responde con el mismo resultado de la primera vez, sin volver a debitar la reserva.
</Aside>

## Registrar el handler

El handler recibe los datos del pago, los entrega al proceso de acreditación del Participante y devuelve el resultado en la respuesta.

<Tabs syncKey="lenguaje">
  <TabItem label="TypeScript">
    ```typescript
    async function settleOfflineTransferHandler(
      request: ServerSettleOfflineTransferRequest,
    ): Promise<ServerSettleOfflineTransferResponse> {
      const sourceFspId      = request.getSourcefspid();
      const destinationFspId = request.getDestinationfspid();
      const offlineTransfer  = request.getOfflinetransfer();

      const transactionId = offlineTransfer.getTransactionid();
      const amount        = offlineTransfer.getAmount();
      const currency      = offlineTransfer.getCurrency();
      const note          = offlineTransfer.getNote();
      const payerId       = offlineTransfer.getPayerid();
      const payerName     = offlineTransfer.getPayername();
      const payeeFspId    = offlineTransfer.getPayeefspid();
      const payeeId       = offlineTransfer.getPayeeid();
      const payeeName     = offlineTransfer.getPayeename();
      const createdAt     = offlineTransfer.getCreatedat();

      const response = new ServerSettleOfflineTransferResponse();
      // La fuente de la respuesta es el Participante receptor (el nuestro)
      response.setSourcefspid(destinationFspId);
      // El destino de la respuesta es quien originó la solicitud
      response.setDestinationfspid(sourceFspId);

      // Acredita el pago offline según el proceso de tu banco.
      // Debe ser idempotente: un transactionId ya procesado devuelve el resultado anterior.
      const resultado = await acreditarPagoOffline({
        transactionId, amount, currency, note,
        payerId, payerName, payeeFspId, payeeId, payeeName, createdAt,
      });

      const result = new SettleOfflineTransferResult();
      result.setTransactionid(transactionId);
      result.setSuccess(resultado.exitoso);
      if (!resultado.exitoso) result.setErrorcode(resultado.codigoError);
      response.setResult(result);

      return response;
    }

    // Registrar el handler en el cliente gRPC
    grpcClient.setSettleOfflineTransferRequestHandlerFn(settleOfflineTransferHandler);
    ```

## Campos del mensaje entrante

| Campo | Tipo | Descripción |
|---|---|---|
| `sourceFspId` | `string` | FSP que origina la solicitud. |
| `destinationFspId` | `string` | FSP al que va dirigida la solicitud (el Participante del pagador). |
| `offlineTransfer` | `OfflineTransfer` | Datos del pago offline a acreditar. Ver tabla siguiente. |

### OfflineTransfer

| Campo | Tipo | Descripción |
|---|---|---|
| `transactionId` | `string` | Identificador único del pago offline. |
| `amount` | `string` | Monto del pago. |
| `currency` | `string` | Moneda del pago (ej. `'MXN'`). |
| `note` | `string` | Concepto o nota del pago. |
| `payerFspId` | `string` | FSP del pagador (el Participante). |
| `payerId` | `string` | Identificador del Cliente pagador (ej. número de celular). |
| `payerName` | `string` | Nombre del pagador. |
| `payeeFspId` | `string` | FSP del beneficiario. |
| `payeeId` | `string` | Identificador del beneficiario (ej. número de celular). |
| `payeeName` | `string` | Nombre del beneficiario. |
| `createdAt` | `string` | Fecha en que se realizó el pago offline entre los dispositivos. |

## Respuesta

| Campo | Tipo | Requerido | Descripción |
|---|---|---|---|
| `sourceFspId` | `string` | Sí | FSP que responde (el Participante). Usa el `destinationFspId` de la solicitud. |
| `destinationFspId` | `string` | Sí | FSP destino de la respuesta. Usa el `sourceFspId` de la solicitud. |
| `result` | `SettleOfflineTransferResult` | Sí | Resultado de la acreditación. Ver tabla siguiente. |
| `error` | `ErrorResponse` | No | No lo uses para reportar rechazos. Ver nota abajo. |

### SettleOfflineTransferResult

| Campo | Tipo | Requerido | Descripción |
|---|---|---|---|
| `transactionId` | `string` | Sí | Identificador del pago offline (mismo que el recibido). |
| `success` | `boolean` | Sí | `true` si el pago se acreditó; `false` si fue rechazado. |
| `errorCode` | `string` | No | Código del motivo de rechazo. Incluir cuando `success` sea `false`. |
