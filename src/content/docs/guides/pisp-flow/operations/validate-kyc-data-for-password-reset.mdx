Cuando un Cliente solicita reiniciar su contraseña desde una app PISP, el módulo 3ppi del Switch envía a tu banco una solicitud `ValidateKycDataForPasswordReset`. Tu banco debe validar que el `curp` y el `accountId` correspondan al `partyId` recibido y responder si el Cliente puede continuar con el proceso.

Para recibir estas solicitudes, debes registrar un **handler** en el cliente gRPC. El cliente invocará esta función cada vez que el módulo 3ppi necesite validar los datos KYC previos al reinicio de contraseña.

<Aside type="caution">
	Verifica siempre que el `curp` y el `accountId` estén asociados al `partyId` antes de permitir el reinicio de contraseña. Si los datos no coinciden o ocurre un error interno, responde con un `ErrorResponse` y establece `canResetPassword` en `false`.
</Aside>

## Registrar el handler

<Tabs syncKey="lenguaje">
	<TabItem label="TypeScript">
		```typescript
		async function handleValidateKycDataForPasswordReset(
			request: ServerValidateKycDataForPasswordResetRequest,
		): Promise<ServerValidateKycDataForPasswordResetResponse> {
			const partyId          = request.partyId;
			const sourceFspId      = request.sourceFspId;
			const destinationFspId = request.destinationFspId;
			const curp             = request.curp;
			const accountId        = request.accountId;

			const response = new ServerValidateKycDataForPasswordResetResponse();
			// La fuente de la respuesta es el banco receptor (el nuestro)
			response.sourceFspId = destinationFspId;
			// El destino de la respuesta es quien originó la solicitud
			response.destinationFspId = sourceFspId;
			response.partyId = partyId;
			response.curp = curp;
			response.accountId = accountId;

			try {
				// Aquí iría: validar que el CURP y el accountId coincidan con el partyId
				const canResetPassword = true; // Simulación de validación exitosa

				response.canResetPassword = canResetPassword;

				return response;
			} catch (error) {
				response.canResetPassword = false;
				response.error = {
					code: 'VALIDATE_KYC_DATA_FOR_PASSWORD_RESET_ERROR',
					message: error instanceof Error ? error.message : 'Error validating KYC data for password reset',
				};

				return response;
			}
		}

		// Registrar el handler en el cliente gRPC
		grpcClient.setValidateKycDataForPasswordResetHandlerFn(handleValidateKycDataForPasswordReset);
		```

## Campos del mensaje entrante (`ServerValidateKycDataForPasswordResetRequest`)

| Campo | Tipo | Descripción |
|---|---|---|
| `partyId` | `string` | Identificador del Cliente (ej. número de celular). |
| `sourceFspId` | `string` | FSP que origina la solicitud (módulo 3ppi del Switch). |
| `destinationFspId` | `string` | FSP al que va dirigida la solicitud (tu banco). |
| `curp` | `string` | CURP del Cliente que solicita el reinicio de contraseña. |
| `accountId` | `string` | Identificador de la cuenta que se usará para validar la identidad del Cliente. |

## Respuesta (`ServerValidateKycDataForPasswordResetResponse`)

La respuesta contiene los mismos identificadores del mensaje entrante, además de un indicador que define si el Cliente puede continuar con el reinicio de contraseña. Si la validación falla, incluye un `ErrorResponse` y establece `canResetPassword` en `false`.

| Campo | Tipo | Requerido | Descripción |
|---|---|---|---|
| `sourceFspId` | `string` | Sí | FSP que responde (tu banco). Usa el `destinationFspId` de la solicitud. |
| `destinationFspId` | `string` | Sí | FSP destino de la respuesta. Usa el `sourceFspId` de la solicitud. |
| `partyId` | `string` | Sí | Identificador del Cliente (mismo que el recibido). |
| `curp` | `string` | Sí | CURP recibido en la solicitud. |
| `accountId` | `string` | Sí | Identificador de la cuenta recibido en la solicitud. |
| `canResetPassword` | `boolean` | Sí | Indica si el Cliente puede continuar con el reinicio de contraseña. |
| `error` | `ErrorResponse` | No | Incluir si los datos KYC no son válidos o si ocurre un error interno. |

## Cuando la validación no es exitosa

Si el `curp` no coincide con el `partyId`, la cuenta no pertenece al Cliente o ocurre un error durante la validación, incluye un `ErrorResponse` en la respuesta y establece `canResetPassword` en `false`. El flujo posterior de restablecimiento de contraseña no debe continuar en ese caso.
