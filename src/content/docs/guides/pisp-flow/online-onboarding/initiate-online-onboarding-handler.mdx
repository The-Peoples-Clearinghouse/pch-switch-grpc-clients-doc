Cuando un Cliente inicia el onboarding en línea desde la app PISP, el módulo 3ppi del Switch envía a tu banco una solicitud `InitiateOnlineOnboarding` con el número de teléfono y el identificador del dispositivo. Tu banco debe **validar que el número de teléfono corresponda a un Cliente existente con su información lista en el banco** y, de ser así, generar un OTP y enviárselo al Cliente por SMS para confirmar la posesión del dispositivo móvil.

El onboarding en línea opera sobre cuentas que ya existen en tu banco. Si el número de teléfono no corresponde a ningún Cliente, o el Cliente no tiene su información lista, el onboarding no puede continuar y debes responder con un error.

Para recibir estas solicitudes, debes registrar un **handler** en el cliente gRPC. El cliente invocará esta función cada vez que el módulo 3ppi inicie un onboarding en línea en tu banco.

<Aside type="note">
  Tu banco es responsable de:
  - Validar que el `phoneNumber` corresponda a un Cliente existente con su información lista en el banco.
  - Registrar el onboarding en curso asociado al `onboardingRequestId`.
  - Generar el OTP y enviarlo por SMS al `phoneNumber` del Cliente.
  - Almacenar la relación entre el `onboardingRequestId` y el OTP generado, para poder validarlo en el siguiente paso.
  - Gestionar el tiempo de vida del OTP. Se recomienda un máximo de **10 minutos**.
</Aside>

<Aside type="caution">
  El handler debe responder siempre dentro del tiempo límite. Si no fue posible iniciar el onboarding o enviar el OTP, responde con `success = false` y un `ErrorResponse` en lugar de no responder.
</Aside>

## Registrar el handler

<Tabs syncKey="lenguaje">
  <TabItem label="TypeScript">
    ```typescript
    async function initiateOnlineOnboardingHandler(
      request: ServerInitiateOnlineOnboardingRequest,
    ): Promise<ServerInitiateOnlineOnboardingResponse> {
      const sourceFspId          = request.getSourcefspid();
      const destinationFspId     = request.getDestinationfspid();
      const phoneNumber          = request.getPhonenumber();
      const deviceId             = request.getDeviceid();
      const onboardingRequestId  = request.getOnboardingrequestid();

      const response = new ServerInitiateOnlineOnboardingResponse();
      // La fuente de la respuesta es el banco receptor (el nuestro)
      response.setSourcefspid(destinationFspId);
      // El destino de la respuesta es quien originó la solicitud
      response.setDestinationfspid(sourceFspId);
      response.setOnboardingrequestid(onboardingRequestId);

      // Valida que el número de teléfono corresponda a un Cliente existente
      // con su información lista en el banco. El onboarding en línea opera
      // sobre cuentas que ya existen.
      if (!clienteExisteConCuentas(phoneNumber)) {
        const error = new ErrorResponse();
        error.setCode('CUSTOMER_NOT_FOUND');
        error.setMessage('El número de teléfono no corresponde a un cliente con cuentas en el banco.');
        response.setSuccess(false);
        response.setError(error);
        return response;
      }

      // Registra el onboarding en curso, genera el OTP, almacena su relación
      // con el onboardingRequestId y envíalo por SMS al número del cliente.
      // Se recomienda que el OTP tenga un tiempo de vida máximo de 10 minutos.
      const enviado = await iniciarOnboardingEnLinea(onboardingRequestId, phoneNumber, deviceId);

      if (!enviado) {
        const error = new ErrorResponse();
        error.setCode('ONLINE_ONBOARDING_FAILED');
        error.setMessage('No fue posible iniciar el onboarding en línea del cliente.');
        response.setSuccess(false);
        response.setError(error);
        return response;
      }

      response.setSuccess(true);

      return response;
    }

    // Registrar el handler en el cliente gRPC
    grpcClient.setInitiateOnlineOnboardingHandlerFn(initiateOnlineOnboardingHandler);
    ```

## Campos del mensaje entrante (`ServerInitiateOnlineOnboardingRequest`)

| Campo | Tipo | Descripción |
|---|---|---|
| `sourceFspId` | `string` | FSP que origina la solicitud (módulo 3ppi del Switch). |
| `destinationFspId` | `string` | FSP al que va dirigida la solicitud (tu banco). |
| `phoneNumber` | `string` | Número de teléfono del Cliente al que se enviará el OTP. |
| `deviceId` | `string` | Identificador del dispositivo del Cliente. |
| `onboardingRequestId` | `string` | Identificador único de la solicitud de onboarding en línea. |

Ver referencia completa: [ServerInitiateOnlineOnboardingRequest](/pch-switch-grpc-clients-doc/reference/server-initiate-online-onboarding-request/)

## Respuesta (`ServerInitiateOnlineOnboardingResponse`)

| Campo | Tipo | Requerido | Descripción |
|---|---|---|---|
| `sourceFspId` | `string` | Sí | FSP que responde (tu banco). Usa el `destinationFspId` de la solicitud. |
| `destinationFspId` | `string` | Sí | FSP destino de la respuesta. Usa el `sourceFspId` de la solicitud. |
| `onboardingRequestId` | `string` | Sí | Identificador de la solicitud (mismo que el recibido). |
| `success` | `bool` | Sí | `true` si el Cliente es válido y el OTP fue enviado; `false` en caso contrario. |
| `error` | `ErrorResponse` | No | Incluir si el Cliente no existe, no tiene su información lista, o no fue posible enviar el OTP. |

Ver referencia completa: [ServerInitiateOnlineOnboardingResponse](/pch-switch-grpc-clients-doc/reference/server-initiate-online-onboarding-response/)

## Cuando el onboarding falla

Si el número de teléfono no corresponde a un Cliente existente con su información lista en el banco, o no fue posible enviar el OTP, responde con `success = false` e incluye un `ErrorResponse` en la respuesta. El onboarding en línea no crea Clientes ni cuentas nuevas: opera únicamente sobre cuentas que ya existen.
