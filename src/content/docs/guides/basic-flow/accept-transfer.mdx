Cuando un participante actúa como banco receptor, el Switch le envía un mensaje `ServerAcceptTransferRequest` solicitando que confirme si la cuenta destino puede recibir los fondos.
El participante debe evaluar la cuenta, actualizar el saldo del beneficiario y responder con `ServerAcceptTransferResponse` dentro del tiempo límite.

Este es el paso 9-11 del flujo de transferencia: ocurre después de que el banco emisor envía `ExecuteTransfer` y antes de que la transferencia sea definitiva.

Para recibir estas solicitudes, debes registrar un **handler** (callback) en el cliente gRPC mediante `setAcceptTransferHanderFn`. El cliente invocará esta función cada vez que el Switch envíe una solicitud de aceptación de transferencia.

<Aside type="caution">
  No responder dentro del tiempo límite equivale a rechazar la transferencia. El handler debe responder siempre, incluso cuando la cuenta no pueda recibir los fondos.
</Aside>

## Verificar la firma de la solicitud

`ServerAcceptTransferRequest` trae `payerSignature` (la firma original del pagador) y `switchRequestSignature` (el Switch sobre esa solicitud). El Switch cubre el contenido canónico de la solicitud **más** el `payerSignature` del pagador no el canónico solo, así podés detectar si el Switch alteró algo entre lo que el payer firmó y lo que te reenvió.

Verificarla es recomendado y deberia hacelo antes de decidir si la cuenta puede recibir los fondos o cualquier otra situación es decir si la firma fue modificada no deberia aceptarse, la validacion se hace contra el CA de firma de Switch.
 [inicializar el cliente](/pch-switch-grpc-clients-doc/getting-started/initialization). El contenido canónico es el mismo que el de `ExecuteTransfer` (ver [Firmar la transferencia](/pch-switch-grpc-clients-doc/guides/basic-flow/execute-transfer#firmar-la-transferencia)), tomado de los campos de `ServerAcceptTransferRequest`.

## Firmar la respuesta

Antes de devolver `ServerAcceptTransferResponse`, firmalo con la llave de firma de transacciones en el campo `payeeSignature`. El Switch valida esta firma igual que valida la del pagador en `ExecuteTransfer`, y la exige en **todas** las respuestas, incluidas las de rechazo.

El contenido canónico es el mismo formato que la respuesta de `ExecuteTransfer`: `transferId|homeTransactionId|errorCode|errorReason` unidos con `|` (`errorCode`/`errorReason` van vacíos cuando aceptás la transferencia).

<Tabs syncKey="lenguaje">

    ```typescript
    const responseCanonical = buildTransferResponseCanonical({

      errorReason: response.getError()?.getMessage(),
    });
    response.setPayeesignature(await transactionSigningHelper.signString(responseCanonical));
    ```

</Aside>

## Registrar el handler

<Tabs syncKey="lenguaje">
  <TabItem label="TypeScript">
    ```typescript
    // Firma la respuesta antes de devolverla — payeeSignature es obligatorio en todos los casos,
    // incluidos los rechazos (ver Firmar la respuesta)
    async function signed(r: ServerAcceptTransferResponse): Promise<ServerAcceptTransferResponse> {
      const canonical = buildTransferResponseCanonical({
        transferId: r.getTransferid(),
        homeTransactionId: r.getHometransactionid(),
        errorCode: r.getError()?.getCode(),
        errorReason: r.getError()?.getMessage(),
      });
      r.setPayeesignature(await transactionSigningHelper.signString(canonical));
      return r;
    }

    async function acceptTransferHandler(
      request: ServerAcceptTransferRequest,
    ): Promise<ServerAcceptTransferResponse> {
      const transferId        = request.getTransferid();
      const homeTransactionId = request.getHometransactionid();
      const threeppiEnabled   = request.getThreeppienabled();
      const note              = request.getNote();

      const response = new ServerAcceptTransferResponse();
      response.setTransferid(transferId);
      response.setHometransactionid(homeTransactionId);
      response.setThreeppienabled(threeppiEnabled);

      // from, to y amount son opcionales — verificar antes de usar
      if (!request.hasFrom() || !request.hasTo() || !request.hasAmount()) {
        const errorResponse = new ErrorResponse();
        errorResponse.setCode('MISSING_REQUIRED_FIELDS');
        errorResponse.setMessage('La solicitud no contiene los campos requeridos.');
        response.setError(errorResponse);
        return signed(response);
      }

      const from   = request.getFrom();
      const to     = request.getTo();
      const amount = request.getAmount();

      // El origen de la respuesta es el banco receptor (el nuestro)
      response.setSourcefspid(to.getFspid());
      // El destino de la respuesta es el banco que inició la transferencia
      response.setDestinationfspid(from.getFspid());

      // Verifica que el Switch no haya alterado la solicitud del payer al reenviarla
      // (ver Verificar la firma de la solicitud)
      const requestCanonical = buildTransferRequestCanonical({
        homeTransactionId: request.getHometransactionid(),
        fromFspId: from.getFspid(),
        fromIdType: from.getIdtype(),
        fromIdValue: from.getIdvalue(),
        toFspId: to.getFspid(),
        toIdType: to.getIdtype(),
        toIdValue: to.getIdvalue(),
        amountType: request.getAmounttype(),
        currencyCode: amount.getCurrencycode(),
        amount: amount.getAmount(),
        scenario: request.getTransactiontype()!.getScenario(),
        subScenario: request.getTransactiontype()!.getSubscenario(),
        initiator: request.getTransactiontype()!.getInitiator(),
        initiatorType: request.getTransactiontype()!.getInitiatortype(),
        threeppiEnabled: request.getThreeppienabled(),
        creationTimestamp: request.getCreationtimestamp(),
      });
      const validSwitchSignature = await transactionSigningHelper.validateSignatureAgainstCA(
        requestCanonical + '|' + request.getPayersignature(),
        request.getSwitchrequestsignature()
      );
      if (!validSwitchSignature) {
        const errorResponse = new ErrorResponse();
        errorResponse.setCode('INVALID_SIGNATURE');
        errorResponse.setMessage('La firma del Switch sobre la solicitud no es válida.');
        response.setError(errorResponse);
        return signed(response);
      }

      // Ejecuta reglas de negocio para determinar si la cuenta puede recibir los fondos
      if (!laCuentaDestinoPuedeRecibirFondos(to.getIdvalue(), amount.getAmount())) {
        const errorResponse = new ErrorResponse();
        errorResponse.setCode('ACCOUNT_NOT_ACTIVE');
        errorResponse.setMessage('La cuenta no está activa o no puede recibir fondos.');
        response.setError(errorResponse);
        return signed(response);
      }

      // Actualizar los saldos del beneficiario

      return signed(response);
    }

    // Registra el handler en el cliente gRPC
    grpcClient.setAcceptTransferHanderFn(acceptTransferHandler);
    ```

    ```java
    // signAcceptTransferResponse declara "throws Exception" y el handler no puede propagarla
    // (Function<ServerAcceptTransferRequest, ServerAcceptTransferResponse> no la declara)
    static ServerAcceptTransferResponse signQuietly(GrpcSyncApiClient client, ServerAcceptTransferResponse response) {
        try {
            return client.signAcceptTransferResponse(response);
        } catch (Exception e) {
            throw new RuntimeException(e);
        }
    }

    grpcClient.setAcceptTransferHandlerFn(req -> {
        String  transferId        = req.getTransferId();
        String  homeTransactionId = req.getHomeTransactionId();
        boolean threeppiEnabled   = req.getThreeppiEnabled();

        ServerAcceptTransferResponse.Builder response = ServerAcceptTransferResponse.newBuilder()
                .setTransferId(transferId)
                .setHomeTransactionId(homeTransactionId)
                .setThreeppiEnabled(threeppiEnabled);

        // From, To y Amount son opcionales — verificar antes de usar
        if (!req.hasFrom() || !req.hasTo() || !req.hasAmount()) {
            response.setError(ErrorResponse.newBuilder()
                    .setCode("MISSING_REQUIRED_FIELDS")
                    .setMessage("La solicitud no contiene los campos requeridos.")
                    .build());
            return signQuietly(grpcClient, response.build());
        }

        // El origen de la respuesta es el banco receptor (el nuestro)
        response.setSourceFspId(req.getTo().getFspId());
        // El destino de la respuesta es el banco que inició la transferencia
        response.setDestinationFspId(req.getFrom().getFspId());

        // Verifica que el Switch no haya alterado la solicitud del payer al reenviarla
        // (ver Verificar la firma de la solicitud)
        try {
            if (!grpcClient.verifyAcceptTransferRequestSignature(req)) {
                response.setError(ErrorResponse.newBuilder()
                        .setCode("INVALID_SIGNATURE")
                        .setMessage("La firma del Switch sobre la solicitud no es válida.")
                        .build());
                return signQuietly(grpcClient, response.build());
            }
        } catch (Exception e) {
            throw new RuntimeException(e);
        }

        // Ejecuta reglas de negocio para determinar si la cuenta puede recibir los fondos
        if (!laCuentaDestinoPuedeRecibirFondos(req.getTo().getIdValue(), req.getAmount().getAmount())) {
            response.setError(ErrorResponse.newBuilder()
                    .setCode("ACCOUNT_NOT_ACTIVE")
                    .setMessage("La cuenta no está activa o no puede recibir fondos.")
                    .build());
            return signQuietly(grpcClient, response.build());
        }

        // Actualizar los saldos del beneficiario

        return signQuietly(grpcClient, response.build());
    });
    ```

## Campos del mensaje entrante (`ServerAcceptTransferRequest`)

| Campo | Tipo | Descripción |
|---|---|---|
| `transferId` | `string` | Identificador de la transferencia asignado por la Cámara. |
| `homeTransactionId` | `string` | Identificador interno del banco emisor. |
| `from` | `Party` | Datos del ordenante (banco y cuenta origen). |
| `to` | `Party` | Datos del beneficiario (banco y cuenta destino). |
| `amount` | `Amount` | Monto y moneda de la transferencia. |
| `amountType` | `string` | Tipo de monto (ej. `'SEND'`). |
| `transactionType` | `TransactionType` | Categorización del tipo de transacción. |
| `note` | `string` | Concepto del pago. |
| `threeppiEnabled` | `boolean` | Indica si la transferencia usa flujo 3PPI. |
| `extensions` | `ExtensionField[]` | Opcional. Pares clave/valor para datos adicionales del participante. |
| `payerSignature` | `string` | Firma original del pagador sobre el contenido canónico de la solicitud. |
| `switchRequestSignature` | `string` | El Switch sobre la solicitud del pagador — ver [Verificar la firma de la solicitud](#verificar-la-firma-de-la-solicitud). |
| `creationTimestamp` | `string` | Epoch en milisegundos, como string, tomado de la solicitud original del pagador. Forma parte del contenido canónico a verificar. |

Ver referencia completa: [ServerAcceptTransferRequest](/pch-switch-grpc-clients-doc/reference/server-accept-transfer-request/)

## Respuesta (`ServerAcceptTransferResponse`)

La respuesta indica al Switch si la transferencia fue aceptada. Si no se incluye `error`, la transferencia se considera aceptada. Si se incluye un `error`, la transferencia es rechazada.

| Campo | Tipo | Requerido | Descripción |
|---|---|---|---|
| `transferId` | `string` | Sí | Mismo `transferId` del mensaje recibido. |
| `homeTransactionId` | `string` | Sí | Mismo `homeTransactionId` del mensaje recibido. |
| `sourceFspId` | `string` | Sí | FSP que origina la respuesta (el banco receptor, el nuestro). |
| `destinationFspId` | `string` | Sí | FSP destino de la respuesta (el banco emisor). |
| `threeppiEnabled` | `boolean` | Sí | Mismo valor recibido en la solicitud. |
| `error` | `ErrorResponse` | No | Omitir para aceptar. Incluir con `code` y `message` para rechazar. |
| `payeeSignature` | `string` | Sí | Firma del beneficiario sobre el contenido canónico de la respuesta — obligatoria en todos los casos, incluidos los rechazos. Ver [Firmar la respuesta](#firmar-la-respuesta). |

Ver referencia completa: [ServerAcceptTransferResponse](/pch-switch-grpc-clients-doc/reference/server-accept-transfer-response/)

## Cuando la cuenta no puede recibir fondos

Si la cuenta destino no está activa o no puede recibir el monto solicitado, incluye un `ErrorResponse` en la respuesta con un código descriptivo.

{/* | Código | Descripción |
|---|---|
| `ACCOUNT_NOT_ACTIVE` | La cuenta destino no está activa. |
| `ACCOUNT_NOT_FOUND` | No se encontró una cuenta asociada al `partyId`. |
| `AMOUNT_EXCEEDS_LIMIT` | El monto supera el límite de recepción configurado. | */}
